# SEBAS PLAY 13.0 — release readiness

Do not change these identifiers to reuse the 12.0 installation.

## Automated checks

The `release-readiness.yml` workflow runs the web TypeScript/production build, independent identity checks, Windows media-server smoke tests, and Roku ZIP packaging as parallel jobs. The Android APK has its own workflow, which verifies the exact package ID before uploading the artifact.

The Windows media server now accepts administrator credentials only in the Authorization Bearer header. Admin credentials in query strings are rejected to reduce exposure through browser history, proxy logs, and copied URLs.

## Supabase backend

The deployed Edge Functions have been copied into `supabase/functions` so the repository contains the source that is actually running:

- `roku-device-sync`
- `sebas-family-profiles` and its PBKDF2 PIN helper

The connected Supabase project reports both functions active and the family-profile, pairing, profile-scoped data, and realtime migrations applied. The live project security advisor currently warns that leaked-password protection is disabled; enable it in Supabase Auth settings before treating account security as fully hardened.

## What CI cannot prove

A green build or generated ZIP does not prove behavior on physical hardware. Final acceptance still requires:
1. Install Android 13.0 beside 12.0 and verify sign-in, playback, seeking, favorites, progress, and profile PIN behavior.
2. Sideload the Roku ZIP and verify pairing, catalog navigation, playback, favorites, and resume progress.
3. Run the Windows setup script on the target Windows laptop, verify firewall/LAN access, and test real MP4/MKV/AVI files. Roku conversion additionally requires FFmpeg.
4. Confirm the laptop and devices are on a reachable network, and use a stable HTTPS tunnel for access outside the home network.

Only publish a final release after these physical-device checks pass.
